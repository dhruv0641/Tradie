## 1. Sprint Objective & Context

The objective of **Sprint S01.01** is to establish the reproducible, hermetic Python 3.12+ engineering environment, static type analysis, formatting, secret detection, and automated CI pipeline before any domain logic or market data code is written.

This sprint enforces the non-negotiable quality boundaries mandated by [AGENTS.md](file:///c:/Users/dobar_zdc9vhh/OneDrive/Desktop/AI%20Tradie/AGENTS.md) §8 and TRD §14:
- Zero untyped function definitions (`mypy --strict`).
- Zero unformatted or style-violating code (`ruff format`, `ruff check`).
- Zero plain-text credentials or API secrets in Git history (`detect-secrets`, `gitleaks`).
- Automated branch protection and test execution via GitHub Actions.

### TASK-01-01-001: Initialize Python 3.12+ Environment and Dependency Management

#### 1. Metadata
- **Task ID**: `TASK-01-01-001`
- **Task Name**: Setup `uv` / `poetry` build configuration and package manifests
- **Primary Owner**: Agent 11 (Technology Agent)

#### 2. Detailed Description & Rationale
Configure the primary repository package manifest (`pyproject.toml`) enforcing Python 3.12+ language constraints. Establish dependency groups separating production runtime dependencies (core data, math, database, web) from development/testing/research dependencies. Generate a deterministic lockfile to guarantee zero dependency drift across environments.

- **Governing Requirements**: TRD §3, §14; TTD §4, §12; NFR-MAINT-1; AGENTS.md §8.

- Build backend: `hatchling` or `flit_core`.
- Python constraint: `>=3.12`.
- Core Runtime Dependencies:
  - `pydantic>=2.8.0` (Canonical data schemas per DDD §5)
  - `pydantic-settings>=2.4.0` (Environment config)
  - `structlog>=24.2.0` (Structured JSON logging per TRD-OBS-1)

  - `numpy>=2.0.0` & `pandas>=2.2.0` (Vectorized quantitative calculations)
  - `httpx>=0.27.0` & `websockets>=12.0` (Market data HTTP & WebSocket streaming)
- Dev / Test Dependencies:

### TASK-01-01-002: Configure Static Analysis, Code Formatting, and Type Checking

#### 1. Metadata
- **Task ID**: `TASK-01-01-002`
- **Task Name**: Configure Ruff, Mypy Strict Mode, and Pre-commit Hooks
- **Primary Owner**: Agent 15 (DevOps Agent) / Agent 16 (Code Review Agent)
- **Reviewer**: Agent 09 (Risk & Safety Agent), Agent 13 (Security Agent)
- **Dependencies**: `TASK-01-01-001`
- **Target Phase**: Phase V0

#### 2. Detailed Description & Rationale
Configure `ruff` as the unified high-performance linter and formatter, replacing flake8/black/isort. Configure `mypy` in full strict mode (`disallow_untyped_defs = true`, `disallow_any_generics = true`, `strict_equality = true`) to enforce strict type contracts. Establish `.pre-commit-config.yaml` including pre-commit hooks for secret detection (`detect-secrets` or `gitleaks`) to enforce TRD-SEC-1.

#### 3. Source Traceability
- **Governing Requirements**: TRD-SEC-1; NFR-SEC-1; NFR-MAINT-1; AGENTS.md §8; review-checklists.md §1.
- **Governing Docs**: [docs/trd.md](file:///c:/Users/dobar_zdc9vhh/OneDrive/Desktop/AI%20Tradie/docs/trd.md), [docs/nfrd.md](file:///c:/Users/dobar_zdc9vhh/OneDrive/Desktop/AI%20Tradie/docs/nfrd.md), [docs/reviews/review-checklists.md](file:///c:/Users/dobar_zdc9vhh/OneDrive/Desktop/AI%20Tradie/docs/reviews/review-checklists.md).

#### 4. Technical Specification & Configuration Specs

##### Ruff Configuration (`ruff.toml` or `[tool.ruff]` in `pyproject.toml`):
- Target version: `py312`
- Line length: 100
- Rule selectors: `["E", "F", "W", "I", "N", "UP", "B", "A", "C4", "SIM", "TCH", "ARG", "PTH", "PL", "RUF"]`
- Disallow unused variables, imports, and deprecated syntax.

##### Mypy Configuration (`mypy.ini` or `[tool.mypy]` in `pyproject.toml`):
```ini
[mypy]
python_version = 3.12
strict = true
warn_return_any = true
warn_unused_configs = true
disallow_untyped_defs = true
disallow_incomplete_defs = true
check_untyped_defs = true
disallow_untyped_decorators = true
no_implicit_optional = true
warn_redundant_casts = true
warn_unused_ignores = true
warn_no_return = true
warn_unreachable = true
strict_equality = true
```

##### Pre-commit Configuration (`.pre-commit-config.yaml`):
Hooks:
- `pre-commit-hooks`: `trailing-whitespace`, `end-of-file-fixer`, `check-yaml`, `check-toml`, `check-added-large-files`.
- `ruff-pre-commit`: `ruff` (linter) with `--fix`, `ruff-format` (formatter).
- `mirrors-mypy`: `mypy` running in strict mode against `src/` and `tests/`.
- `gitleaks`: Pre-commit hook scanning staged commits for API keys, tokens, and credentials.

#### 5. Expected File Changes
- **[NEW]** `.pre-commit-config.yaml`
- **[NEW]** `ruff.toml` (or configured inside `pyproject.toml`)
- **[NEW]** `mypy.ini` (or configured inside `pyproject.toml`)

#### 6. Step-by-Step Implementation Instructions
1. Add Ruff and Mypy strict configuration sections into `pyproject.toml` or standalone config files.
2. Create `.pre-commit-config.yaml` with pre-commit hooks for ruff, mypy, and secret detection.
3. Install the pre-commit git hooks: `pre-commit install`.
4. Create a dummy Python file `src/__init__.py` and verify `ruff check .` and `mypy src` pass cleanly.
5. Create a test commit with an intentional type error and verify the pre-commit hook blocks the commit.

#### 7. Acceptance Criteria
- [ ] `ruff check .` and `ruff format --check .` execute and pass with zero violations.
- [ ] `mypy src` passes in strict mode with zero untyped definitions.
- [ ] Secret detection hook blocks any commit containing dummy API credentials or secret tokens.
- [ ] Pre-commit hooks run automatically on `git commit`.

#### 8. Verification Commands
```bash

ruff format --check .

# Execute strict typecheck

# Execute pre-commit validation against all files
```

### TASK-01-01-003: Configure Pytest Framework and CI Workflow

#### 1. Metadata
- **Task ID**: `TASK-01-01-003`
- **Task Name**: Setup Pytest Test Harness and GitHub Actions CI Pipeline
- **Primary Owner**: Agent 14 (QA / Testing Agent)
- **Reviewer**: Agent 09 (Risk & Safety Agent), Agent 15 (DevOps Agent)
- **Dependencies**: `TASK-01-01-002`
- **Target Phase**: Phase V0

#### 2. Detailed Description & Rationale
Configure the Pytest test harness and directory structure mirroring the architectural subsystems (`tests/unit/`, `tests/integration/`, `tests/safety/`). Configure GitHub Actions CI workflow to run linting, strict typing, tests, and branch coverage checks on every push and pull request. Enforce the non-negotiable **100% branch coverage on safety-critical modules** (NFR-SAFE-6) and **$\ge 80\%$ line coverage on general modules** (NFR-TEST-3).

#### 3. Source Traceability
- **Governing Requirements**: TRD-CI-1, TRD-CI-2; NFR-TEST-1, NFR-TEST-3; NFR-SAFE-6; AGENTS.md §8.
- **Governing Docs**: [docs/trd.md](file:///c:/Users/dobar_zdc9vhh/OneDrive/Desktop/AI%20Tradie/docs/trd.md), [docs/nfrd.md](file:///c:/Users/dobar_zdc9vhh/OneDrive/Desktop/AI%20Tradie/docs/nfrd.md), [AGENTS.md](file:///c:/Users/dobar_zdc9vhh/OneDrive/Desktop/AI%20Tradie/AGENTS.md).

#### 4. Technical Specification & Directory Architecture

##### Directory Layout:
```
tests/
├── conftest.py                # Shared pytest fixtures (mock clocks, dummy candles)
├── unit/                      # Fast isolated component unit tests
│   ├── test_foundation.py
│   └── ...
├── integration/               # Multi-component & database integration tests
│   └── ...
└── safety/                    # Isolated safety-critical boundary tests (NFR-SAFE-6)
    └── ...
```

##### Pytest Configuration (`pytest.ini` or `[tool.pytest.ini_options]` in `pyproject.toml`):
```ini
[tool.pytest.ini_options]
minversion = "8.0"
addopts = "-ra -q --strict-markers --cov=src --cov-branch --cov-report=term-missing --cov-report=xml"
testpaths = ["tests"]
python_files = ["test_*.py"]
python_classes = ["Test*"]
python_functions = ["test_*"]
markers = [
    "safety: Safety-critical risk and kill-switch tests (mandatory 100% branch coverage)",
    "integration: Tests requiring external services or databases",
    "unit: Fast isolated unit tests",
]
```

##### GitHub Actions CI Workflow (`.github/workflows/ci.yml`):
- Triggers: `push` on `main`, `develop`; `pull_request` on all branches.
- Job 1: `lint-and-typecheck`:
  - Runs `ruff check .` and `ruff format --check .`.
  - Runs `mypy src tests`.
- Job 2: `test-and-coverage`:
  - Spins up PostgreSQL / TimescaleDB service container.
  - Runs `pytest`.
  - Enforces general line coverage $\ge 80\%$ via `--cov-fail-under=80`.
  - Verifies 100% branch coverage on safety paths (`src/risk_engine/`, `src/supervisor/`, `src/kill_switch/`).
- Job 3: `security-audit`:
  - Runs `gitleaks` or `detect-secrets` scan.
  - Runs `pip-audit` or `safety` to check for known CVEs in dependencies.
