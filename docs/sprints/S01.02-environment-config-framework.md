## 1. Sprint Objective & Context

The objective of **Sprint S01.02** is to implement the centralized, environment-isolated configuration engine (`src/config/settings.py`) and the unified structured JSON logging subsystem (`src/utils/logging.py`).

This sprint directly enforces:
1. **TRD-DEPLOY-2**: Strict separation of configuration between research, paper, and live environments — no live credentials or risk parameters may leak into research runs.
2. **TRD-OBS-1 & NFR-AUDIT-1**: Structured JSON logging emitting standard contextual keys (timestamp UTC, log level, module, correlation ID, execution duration) for 100% auditability.
3. **Fail-Fast Startup**: If any required environment variable is missing or malformed, the system must abort immediately on startup with a descriptive error.

## 5. Detailed Task Specifications

### TASK-01-02-001: Implement Structured Logging Framework

#### 1. Metadata
- **Task ID**: `TASK-01-02-001`
- **Task Name**: Implement Structlog JSON Structured Logging Engine
- **Primary Owner**: Agent 11 (Technology Agent)
- **Reviewer**: Agent 16 (Code Review Agent)
- **Dependencies**: Sprint S01.01 completion

#### 2. Detailed Description & Technical Specification
Implement `src/utils/logging.py` using `structlog` to emit machine-parseable JSON logs in production/CI, while supporting colored console formatting for local development. Every log entry must include:
- `timestamp`: ISO-8601 UTC timestamp with millisecond precision (`YYYY-MM-DDTHH:MM:SS.mmmZ`).
- `level`: Log level (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`).
- `module`: Python logger name / module source.
- `correlation_id`: Context variable tracking end-to-end request or decision cycle.
- `event`: Primary human-readable event message.
- Contextual keyword arguments serialized as JSON attributes.

#### 3. Expected File Changes
- **[NEW]** `src/utils/__init__.py`
- **[NEW]** `src/utils/logging.py`
- **[NEW]** `tests/unit/test_logging.py`

#### 4. Acceptance Criteria
- [ ] In non-development mode (`ENVIRONMENT != "local"`), output is valid, parseable single-line JSON.
- [ ] Correlation ID bound to context propagates to all log statements within the call stack.
- [ ] Unit tests verify standard fields are present on log output.

### TASK-01-02-002: Implement Environment-Aware Configuration Loader

#### 1. Metadata
- **Task ID**: `TASK-01-02-002`
- **Task Name**: Implement Pydantic Settings Configuration Engine
- **Primary Owner**: Agent 12 (Low-Level Engineering Agent)
- **Reviewer**: Agent 09 (Risk & Safety Agent), Agent 13 (Security Agent)
- **Dependencies**: `TASK-01-01-001`

#### 2. Detailed Description & Technical Specification
Implement `src/config/settings.py` and `src/config/models.py` using `pydantic-settings`:
- Model `DatabaseConfig`: PostgreSQL host, port, user, password (`SecretStr`), database name, pool size, SSL mode.
- Model `RiskConfig`: Hard limits from RTLD §14 (`max_daily_loss_pct`, `max_drawdown_pct`, `max_position_size_pct`, `max_exposure_pct`).
- Model `BrokerConfig`: Broker name, API key (`SecretStr`), API secret (`SecretStr`), paper vs. live flag.
- Master Model `AppConfig`: `environment: Literal["research", "paper", "live", "test"]`, sub-configs, version tag.
- Loading Logic: Reads `.env.{environment}` based on `AI_TRADER_ENV` environment variable.
- Validation: Fails immediately if sensitive keys are missing in live mode.

#### 3. Expected File Changes
- **[NEW]** `src/config/__init__.py`
- **[NEW]** `src/config/models.py`
- **[NEW]** `src/config/settings.py`
- **[NEW]** `tests/unit/test_config.py`
- **[NEW]** `.env.example`

#### 4. Acceptance Criteria
- [ ] `AppConfig` loads valid `.env.example` without exceptions.
- [ ] Missing mandatory database URL raises `pydantic.ValidationError` with exact field error.
- [ ] Secrets wrapped in `SecretStr` never leak into string representation or logs (`***`).
- [ ] 100% test coverage on configuration loader.
