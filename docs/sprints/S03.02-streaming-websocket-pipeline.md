## 1. Sprint Objective & Context

The objective of **Sprint S03.02** is to implement the asynchronous real-time market data streaming pipeline (`src/data/streaming.py`). This pipeline ingests low-latency WebSocket ticks and Level 2 market depth, manages socket heartbeats and automated reconnection with exponential backoff, buffers and aggregates ticks into closed 1-minute and 5-minute `OHLCVCandle`s, and persists closed bars to TimescaleDB.

This infrastructure is essential for Phase V4 Paper Trading and Phase V5 Live Trading, while being verified in Phase V0 using synthetic tick generators and mock broker feeds.

## 5. Detailed Task Specifications

### TASK-03-02-001: Implement Streaming WebSocket Feed Ingestion Pipeline

#### 1. Technical Specification
Implement `src/data/streaming.py` and `src/data/aggregator.py`:
- `WebSocketFeedHandler`:
  - Connects to broker WebSocket endpoint using TLS.
  - Heartbeat monitor: Sends ping every 10 seconds; if no pong within 5 seconds, triggers reconnect.
  - Reconnect strategy: Exponential backoff with jitter ($1\text{s}, 2\text{s}, 4\text{s}, 8\text{s}, \dots, \max 60\text{s}$).
  - Parses binary or JSON ticks: `(instrument, timestamp, ltp, volume, bid, ask)`.
- `CandleAggregator`:
  - Maintains rolling bar state for subscribed timeframes (`1m`, `5m`).
  - On first tick in new bar interval, seals previous candle, validates via `DataValidationPipeline` (Sprint S04.01), and emits `OHLCVCandle`.
  - Flushes closed candles asynchronously to TimescaleDB buffer.
- Disconnection Alerting: Emits `STALE` status event to `MarketState` immediately upon socket loss.
