## 1. Sprint Objective & Context

The objective of **Sprint S02.02** is to implement the hybrid storage architecture specified in DDD §6, TRD §6, and TTD §6:
1. **Transactional & Real-Time Storage (PostgreSQL 16+ with TimescaleDB)**: Hypertables for real-time OHLCV streaming candles, ACID transactional tables for orders, positions, risk states, and append-only immutable tables for `decision_records` and `trade_evaluations`.
2. **High-Throughput Analytics Storage (Partitioned Parquet Archive)**: Partitioned by `instrument` and `year/month` using `pyarrow` for multi-year historical backtesting and feature engineering without degrading live database performance.
3. **Automated Migration Pipeline**: Alembic version-controlled DDL migrations with forward and rollback capabilities.

## 5. Detailed Task Specifications

### TASK-02-02-001: Setup PostgreSQL / TimescaleDB Database and Alembic Migrations

#### 1. Technical Specification
Configure SQLAlchemy 2.0 and Alembic to manage database schema:
- Tables:
  1. `ohlcv_candles`: `(instrument, timestamp, open, high, low, close, volume, turnover, timeframe, quality_state)`. Converted to TimescaleDB hypertable partitioned on `timestamp` (chunk time interval: 7 days).
  2. `decision_records`: Immutable append-only audit table. Primary key `decision_record_id (UUID)`. Indexed on `instrument`, `timestamp`, `decision`.
  3. `trade_evaluations`: Immutable post-trade evaluation table. Primary key `trade_id (UUID)`.
  4. `order_submissions`: Execution tracking. Indexed on `client_order_id`, `broker_order_id`, `timestamp`.
  5. `positions`: Current portfolio state. Unique constraint on `instrument`.
  6. `model_versions`: Model registry metadata and validation metrics.
- Enforce append-only integrity: Create SQL trigger or rule blocking `UPDATE` or `DELETE` on `decision_records`.

### TASK-02-02-002: Implement Partitioned Parquet Storage Manager

#### 1. Technical Specification
Implement `src/infrastructure/parquet_store.py` using `pyarrow.dataset`:
- Storage Layout:
  `data/historical/{timeframe}/{instrument}/year={YYYY}/month={MM}/data.parquet`
- Class `ParquetHistoricalStore`:
  - `write_candles(candles: list[OHLCVCandle]) -> int`: Deduplicates on `(instrument, timestamp)` and writes partitioned Snappy-compressed Parquet files.
  - `read_candles(instrument: str, start_time: datetime, end_time: datetime, timeframe: str) -> list[OHLCVCandle]`: Returns point-in-time ordered candles strictly within `[start_time, end_time)`.
  - Guarantees zero lookahead: Slicing must strictly exclude timestamps $\ge end\_time$.
- Performance target: Reading 100,000 candles takes $<50$ms.
