## 1. Sprint Objective & Context

The objective of **Sprint S04.02** is to implement the real-time staleness detection monitor and downstream trade suppression gate (`StalenessMonitor` in `src/data/staleness_monitor.py`).

Per FRD-DATA-9 and RTLD §11:
1. If the elapsed time since the last valid tick on an instrument exceeds the maximum allowable staleness threshold (configured to 10 seconds per NFR-DATA-1), the system must immediately mark the instrument state as `STALE`.
2. Any `STALE` or `QUARANTINED` data condition must automatically suppress trading decisions, compelling the Supervisor Decision Gate to output `NO_TRADE` or `HOLD` (FRD-AGG-4).
3. Upon completion and verification of this sprint, Phase V0 achieves **Gate G0** exit readiness.

## 5. Detailed Task Specifications

### TASK-04-02-001: Implement Staleness Detector and Quarantine Suppression Filter

#### 1. Technical Specification
Implement `src/data/staleness_monitor.py` and `src/data/suppression_gate.py`:
- `StalenessMonitor`:
  - Maintains `dict[str, datetime]` tracking the wall-clock arrival timestamp of the last valid tick/bar per instrument.
  - Method `check_staleness(instrument: str, current_time: datetime) -> StalenessStatus`:
    - Computes $\Delta t = current\_time - last\_arrival\_time$.
    - If $\Delta t > max\_staleness\_seconds$ (default: 10.0s):
      - Returns `StalenessStatus(is_stale=True, elapsed_seconds=Delta_t, reason="TICK_TIMEOUT")`.
      - Emits structured warning log.
- `SuppressionGate`:
  - Inspects `candle.quality_state` and `staleness_status.is_stale`.
  - If `quality_state == "QUARANTINED"` or `is_stale == True`:
    - Short-circuits decision evaluation, forcing `MarketState.data_quality = "STALE"` or `"QUARANTINED"`.
    - Downstream Decision Gate outputs `decision = "NO_TRADE"` with `reason = "DATA_QUALITY_SUPPRESSION"`.
