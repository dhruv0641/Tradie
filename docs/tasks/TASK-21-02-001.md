## 1. Problem Statement & Objective
Implement `ModelPromotionGate` and multi-dimensional comparison logic enforcing empirical evidence superiority over active baseline models and mandatory operator sign-off before live production promotion.

---

## 2. Requirements Lineage & Technical Specifications

- **Task ID**: `TASK-21-02-001`
- **Task Name**: Implement `ModelPromotionGate` and Multi-Dimensional Comparison
- **Description**: Implement `src/governance/promotion_gate.py` comparing candidate vs. current production model per MLD §9.2:
  - Candidate Sharpe $\ge$ Production Sharpe and $\ge 0$
  - Candidate Max Drawdown $\le$ Production Drawdown $\times 1.10$
  - Multi-stage empirical validation passed (`ValidationRunRecord.overall_passed = True`)
  - Operator manual sign-off token check (`operator_signoff`) (BRD §11 item 6, ADD §8.4)
- **Purpose**: Enforce that model promotion occurs strictly on evidence with human oversight (FRD-LEARN-4, FRD-LEARN-5, ADD §8.3/§8.4).
- **Source Requirements**: FRD-LEARN-4, FRD-LEARN-5, FRD-LEARN-8; ADD §8.3, §8.4, §12; MLD §9.2; BRD BR-6.
- **Source Documents**: `docs/mld.md`, `docs/add.md`, `docs/brd.md`.
- **Dependencies**: `TASK-21-01-001`.
- **Inputs**: Candidate and baseline `ModelVersion`, `ValidationRunRecord`, operator sign-off token.
- **Outputs**: `src/governance/promotion_gate.py`, `src/domain/governance_event.py` (`PromotionEvent`).
- **Implementation Notes**: Atomically flips candidate to `status = "promoted"` and prior baseline to `status = "superseded"`, recording cryptographic audit `PromotionEvent`.
- **Files/Modules Changed**: `src/governance/promotion_gate.py`, `src/domain/governance_event.py`, `tests/unit/governance/test_promotion_gate.py`.
- **Acceptance Criteria**: Rejects candidate if any metric underperforms; requires operator sign-off for live promotion.
- **Definition of Done**: 100% branch and statement coverage on `ModelPromotionGate` (`80/80` lines, `16/16` branches).
