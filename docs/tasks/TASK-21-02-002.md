## 2. Requirements Lineage & Technical Specifications

- **Task ID**: `TASK-21-02-002`
- **Task Name**: Implement `RollbackMonitor` and Automated Production Reversion
- **Description**: Implement `src/governance/rollback_monitor.py` per SLD §7:
  - Continuously track rolling 30-trade live performance of active production model.
  - Drawdown ceiling breach ($\ge 8.0\%$) triggers immediate rollback.
  - Consecutive losses ($\ge 5$) triggers immediate rollback.
  - Rolling win rate drops below floor ($< 30\%$) triggers rollback.
  - Rolling Sharpe drops below validated expectation $- 1\text{ SE}$ across 2 consecutive windows triggers automated rollback.
  - Pause promotions if $\ge 2$ rollbacks occur within 90 days (SLD §8).
- **Purpose**: Provide autonomous safety backstop against post-promotion model degradation (FRD-LEARN-7, SLD §7, SOW §6.8).
- **Source Requirements**: FRD-LEARN-6, FRD-LEARN-7, FRD-LEARN-8; ADD §8.4; SLD §7.2, §8; SOW §6.8 (V7).
- **Source Documents**: `docs/sld.md`, `docs/add.md`, `docs/sow.md`, `docs/frd.md`.
- **Dependencies**: `TASK-21-02-001`, `TASK-17-02-001`.
- **Inputs**: Realized live trade stream (`TradeEvaluation`), active and fallback `ModelVersion`.
- **Outputs**: `src/governance/rollback_monitor.py`, `src/domain/governance_event.py` (`RollbackEvent`).
- **Implementation Notes**: Reverts active model to `status = "rolled_back"`, restores prior model to `status = "promoted"`, and logs `RollbackEvent`.
- **Files/Modules Changed**: `src/governance/rollback_monitor.py`, `tests/unit/governance/test_rollback_monitor.py`.
- **Acceptance Criteria**: Injected degraded performance triggers automated reversion to prior model within 1 trade cycle; repeated rollbacks halt candidate promotion pipeline.
- **Definition of Done**: 100% branch and statement coverage on `RollbackMonitor` (`98/98` lines, `22/22` branches).
